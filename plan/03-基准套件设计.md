# plan/03-基准套件设计

仓库 `HWS-formal-math-navigator`（形式化数学库导航与证明骨架生成器）。基准日：**2026-10-16**。

> 本文件为阶段 0 产出，定义基准套件与覆盖度口径。

---

## 一、基准设计原则

### 1.1 核心原则

| 原则 | 落点 |
|------|------|
| **真值 = Lean 内核编译结果** | 不合成真值台账；内核判定 = 唯一真值 |
| **预置快照** | 基准用预置模型输出快照，不依赖当场跑模型 |
| **覆盖度双登记** | 按题型/定理域列最低覆盖项；分母反射自代码常量 |
| **探活** | 基准含"坏实现被判未达标"的探活用例 |
| **降级路径实测** | 无 Lean 工具链时降级路径必须真实存在 |

### 1.2 基准分层

| 层级 | 内容 | 运行方式 |
|------|------|----------|
| **L1 单元测试** | 各模块确定性逻辑 | pytest |
| **L2 集成测试** | 端到端流程 | pytest |
| **L3 基准测试** | 检索 Recall@k / MRR、骨架编译通过率、依赖图完整率 | `python -m hws_formal_math bench` |
| **L4 探活测试** | 坏实现被判未达标 | pytest（变异验证） |

## 二、检索基准（Recall@k / MRR）

### 2.1 指标定义

| 指标 | 定义 | 目标 |
|------|------|------|
| **Recall@k** | Top-k 中包含真值定理的比例 | ≥ 0.7（k=10） |
| **MRR** | 平均倒数排名 | ≥ 0.5 |

## 五、覆盖度双登记

### 5.1 覆盖度口径

| 维度 | 最低覆盖项 | 分母来源 |
|------|------------|----------|
| **题型** | 代数、分析、数论、组合 | 代码常量 `DOMAIN_MIN_COVERAGE` |
| **定理域** | 每个域 ≥ 5 个定理 | 索引元数据 |
| **难度** | 简单、中等、困难 | 测试用例集 |

### 5.2 覆盖度 manifest

```json
{
  "version": "1.0",
  "domains": {
    "algebra": {"min_theorems": 5, "actual": 12, "status": "verified"},
    "analysis": {"min_theorems": 5, "actual": 8, "status": "verified"},
    "number_theory": {"min_theorems": 5, "actual": 10, "status": "verified"},
    "combinatorics": {"min_theorems": 5, "actual": 6, "status": "verified"}
  },
  "difficulties": {
    "easy": {"min_cases": 10, "actual": 12, "status": "verified"},
    "medium": {"min_cases": 10, "actual": 10, "status": "verified"},
    "hard": {"min_cases": 5, "actual": 8, "status": "verified"}
  },
  "generated_by": "tools/gen_coverage.py",
  "generated_at": "2026-10-16",
  "sha256": "abc123..."
}
```

### 5.3 覆盖度守门

| 纪律 | 落点 |
|------|------|
| **新增题型无用例 → 报错** | 生成器检查覆盖度；不达标即 exit 1 |
| **分母反射自代码常量** | 覆盖度阈值写进代码，不写进文档 |
| **覆盖度双登记** | manifest 中登记"最低项"与"实际项" |

## 六、探活测试

### 6.1 探活原则

| 原则 | 落点 |
|------|------|
| **坏实现被判未达标** | 注入缺陷 → 基准必须报未达标 |
| **探活打在消费处** | 测试用例引用定义处，不重复 |

### 6.2 探活用例

```python
# tests/test_bench_probe.py

def test_retrieval_probe_bad_implementation():
    """探活：坏实现（返回空列表）必须被判未达标"""
    bad_retriever = lambda query: []
    result = run_retrieval_bench(bad_retriever, cases=RETRIEVAL_CASES)
    assert result["passed"] == False, "坏实现应被判未达标"

def test_skeleton_probe_bad_implementation():
    """探活：坏实现（全返回 fail）必须被判未达标"""
    bad_generator = lambda prop: {"status": "FAIL"}
    result = run_skeleton_bench(bad_generator, cases=SKELETON_CASES)
    assert result["passed"] == False, "坏实现应被判未达标"

def test_depgraph_probe_bad_implementation():
    """探活：坏实现（漏检断链）必须被判未达标"""
    bad_analyzer = lambda theorems: {"broken_refs": []}
    result = run_depgraph_bench(bad_analyzer, cases=DEPGRAPH_CASES)
    assert result["passed"] == False, "坏实现应被判未达标"
```

## 七、降级路径测试

### 7.1 降级场景

| 场景 | 预期行为 |
|------|----------|
| **无 Lean 工具链** | 检索/依赖图可用；内核验证标注"未执行" |
| **无模型端点** | 骨架生成关闭；接受已形式化输入 |
| **无索引数据** | 提示用户构建索引；不崩溃 |

### 7.2 降级测试

```python
# tests/test_degradation.py

def test_no_lean_retrieval_still_works():
    """无 Lean 工具链时检索仍可用"""
    with mock.patch("shutil.which", return_value=None):
        result = retriever.search("加法结合律")
        assert result is not None
        assert len(result) > 0

def test_no_lean_kernel_verification_marked_skipped():
    """无 Lean 工具链时内核验证标注"未执行"""
    with mock.patch("shutil.which", return_value=None):
        result = kernel.verify("#eval 1 + 1")
        assert result["status"] == "SKIPPED"
        assert result["reason"] == "lean_not_available"

def test_no_model_skeleton_generation_disabled():
    """无模型端点时骨架生成关闭"""
    config = ModelConfig(enabled=False)
    gateway = ModelGateway(config)
    with pytest.raises(ModelDisabledError):
        gateway.generate_skeleton("测试命题")
```
