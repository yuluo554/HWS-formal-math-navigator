# 技术报告：形式化数学库导航与证明骨架生成器

仓库 `HWS-formal-math-navigator`。基准日 **2026-10-18**（v0.1.1 修订）。

本报告对应 plan/01 §三 第 3 项"技术报告"，逐节说明实现口径与可核验证据。
所有数字均可由仓库内命令复算，不写不可复现的估计值。

---

## 一、索引抽取：只存元数据，不存源码

**输入**：用户自备的 mathlib4 快照（固定 commit）。
**输出**：`data/index/theorems.jsonl` + `manifest.json`。

抽取流程（`tools/build_index.py`）：

1. 递归扫描 `<mathlib4>/src/**/*.lean`，过滤隐藏目录，路径排序保证确定性；
2. 逐行匹配 `theorem|lemma|def|inductive|structure|class|instance` 声明，
   按括号深度找到签名冒号，跨行续读直到括号平衡，剥离 `--` 注释与 `:=` 后的证明体；
3. 解析 `import` 语句得到模块级依赖（去重 + 排序）；
4. 写 `theorems.jsonl`（按 `(module, name)` 排序、JSON key 排序）；
5. 写 `manifest.json`：`index_kind` / `upstream_commit` / `sha256` / `theorem_count` /
   `domain_coverage`。

**溯源纪律（v0.1.1 修订）**：`build_index_with_commit()` **拒绝** `unknown` 作为 commit，
manifest 不再出现 `"commit_hash": "unknown"`。随包分发的是 **35 条精选样例索引**，
manifest 显式写 `index_kind: "curated-sample"` 与 `provenance_note`，不冒充全量索引。
全量索引的构建命令写在 README「索引：随包是样例，全量需自建」。

**为什么不做全量随包**：mathlib4 源码数 GB、抽取结果数十万行；随包分发既不现实
（Release 体积）也违反"不存源码/只存元数据"的设计边界。样例索引的作用是
**让离线检索、依赖图、基准在任何机器上可复跑**，而不是提供全库召回。

## 二、检索：BM25，零模型依赖

| 参数 | 值 |
|---|---|
| k1 | 1.2 |
| b | 0.75 |
| 字段权重 | 定理名 > 签名 > 模块名 |
| 返回 | Top-K（默认 10），含 `match_fields` 命中证据 |

**中文查询**：`data/index/query_aliases.json` 提供确定性别名表（"加法"→`add`、
"结合律"→`assoc` 等），按词长降序一次性替换；未覆盖的词按原样分词，
**不做猜测、不引入模型**。别名表缺失时静默降级为空表（检索仍可用，只是中文命中率降低）。

**确定性**：分词与打分均为纯函数；`tests/test_retriever.py` 断言同输入双跑结果逐字段一致。

## 三、内核验证：硬真值，三态

`KernelVerifier` 调用用户自备的 Lean 工具链编译代码片段，判定结果分三态：

| 状态 | 含义 |
|---|---|
| `PASS_NO_SORRY` | 编译通过且无 `sorry` |
| `PASS_WITH_SORRY` | 编译通过但含 `sorry`（**不算证明成功**） |
| `FAIL` | 编译失败（附错误定位） |
| `SKIPPED` | 未安装 Lean —— 如实标注"未执行"，**不冒充通过** |

**边界**：工具只对声明的代码片段 / 预编译缓存做验证，不对 mathlib4 全库重编译；
Lean/elan 是用户自备前置条件。`bench --suite skeleton` 在无 Lean 时报
`not_enabled` 并 exit 1，CI 有一条断言专门验证这一点。

## 四、依赖图：确定性图算法 + index_gap 语义

`DependencyGraph.build(names)` 以给定定理集合为起点，沿模块级依赖边扩展，
输出节点、边、断链（`broken_refs`）、索引缺口（`index_gaps`）与最短路径。

**关键语义**：`index_gap`（索引未覆盖该模块）与"定理不存在"是两件事，
报告中分列呈现。这是本项目"判定不虚高"纪律在图算法上的落点。

**导出**：`export_html()` 生成单文件 HTML，**零外链**（无 CDN、无 http(s) 引用），
断网可开；`tests/test_viewer.py` 对产物做 `http://` / `https://` 扫描断言。

## 五、桌面查看器（v0.1.1 新增实现）

形态定义见 `plan/04` §3.4 与 `delivery-forms.md` 的"形态自查表"：

| 项 | 落点 |
|---|---|
| 主入口 | `hws-formal-math-viewer`（PyInstaller 产物）/ `python -m hws_formal_math.viewer` |
| 主控件 | 「检索定理」按钮、结果表、导出按钮 |
| 接到业务函数 | `ViewerController.search` / `build_graph` / `export_html` |
| 断言 | `tests/test_viewer.py`（控制器层 6 条 + 接线 AST 4 条 + 打包 2 条） |
| 产物 | Release zip 内 `hws-formal-math-viewer[.exe]` |

**为什么拆 controller**：窗口代码不可在 CI（无显示器）里跑，而"按钮有没有接线"
是本次要根治的缺陷。因此业务逻辑全部下沉到 `viewer/controller.py`（零 Qt），
窗口只做控件↔控制器接线；测试既覆盖控制器行为，又用 AST 断言
`search_button.clicked.connect` / `export_button.clicked.connect` 真实存在。

**依赖缺失语义**：未装 PySide6 时 `--selftest` 仍可跑（零 Qt 路径），
窗口模式返回 **3**，不静默退化为成功。

## 六、基准与覆盖度

| 套件 | 数据 | 无 Lean 时 |
|---|---|---|
| `retrieval` | `tests/fixtures/retrieval_cases.json`（10 例，含真值定理名） | 可用 |
| `depgraph` | `tests/fixtures/depgraph_cases.json`（5 例，含节点/边/index_gap 期望） | 可用 |
| `skeleton` | 预置模型输出快照 + Lean 内核真值 | `not_enabled`（exit 1，不冒充通过） |

覆盖度口径：按题型/定理域设最低覆盖项，写进 manifest；新增题型而无用例 → 生成器报错。
分母反射自代码常量（`SUITE_NAMES`），不手写。

## 七、复现步骤

```bash
pip install -e ".[dev]"
pytest tests/ -q                       # 全量测试
hws-formal-math selftest               # 索引/引擎自检
hws-formal-math bench --suite retrieval
hws-formal-math bench --suite depgraph
hws-formal-math-viewer --selftest      # 查看器四步链路
```

全量索引（可选，需自备 mathlib4）：

```bash
python tools/build_index.py --mathlib4 ./mathlib4 \
    --commit-hash $(git -C mathlib4 rev-parse HEAD) --output data/index
```

## 八、已知边界

- 随包索引为 35 条样例，检索召回仅代表样例域，不代表全库能力；
- 签名是便于演示的简化写法，非 mathlib4 逐字抽取（`provenance_note` 已声明）；
- 内核验证需用户自备 Lean；未装时该套件如实 `not_enabled`；
- 骨架生成依赖模型端点（默认关闭），形式化忠实度不承诺自动保证。
