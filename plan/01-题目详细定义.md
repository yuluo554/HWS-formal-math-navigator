# 模拟项目题：形式化数学库导航与证明骨架生成器

> **性质**：自拟模拟项目题（**不参赛**，成果发布 GitHub 公开仓库）。交付形式为 **CLI 为主 + 轻桌面查看器**（PyInstaller 打包 Windows exe，GitHub Release 附安装包）。**检索与依赖图功能离线即用、零模型依赖**；模型接入与 Lean 工具链均为可插拔/用户自备的前置条件。
> **目标产出**：GitHub 公开仓库（本地目录 `HWS-formal-math-navigator`，`HWS-` 为本批命名标签；仓库纯净名 `formal-math-navigator`）。
> **版本史**：v1（2026-10-15 定稿）—— 首版即含「模型在环但审计核心零模型可跑」纪律、**「Lean 工具链为用户自备前置条件」的交付物可达性边界**、以及「mathlib4 以版本化快照接入、只入索引元数据」的设计。
> **定位宣言**：LLM 聊数学会"**看起来对**"，Lean 内核只认真假。本工具把**长上下文检索**（在超大 mathlib4 库中找可复用定理）与**证明骨架生成**接在**可执行的证明检查器**上，让"生成的证明"从"读着像对"变成**可判定的对象**——LLM 聊天给不了持久状态（版本化库索引）、进入工作流的交付物（可编译骨架）与可复现测量基建（内核判定基准），本工具是形式化数学时代的证明脚手架与判定台。

---

## 一、项目介绍

**痛点**。形式化数学（Lean 4 / mathlib4）的门槛极高：mathlib4 是**数万条定理、数百万行**的超大库，人在其中找"哪条定理能复用"几乎不可能；模型生成的 Lean 代码常**看似合理却编译不过**（hallucinated lemma name、类型不匹配、`sorry` 掩盖空洞）；而"证明对不对"这件事，**只有内核能给确定答案**——但把模型接上内核做闭环的工具不存在。现有工具各管一段：检索工具、依赖图工具、autoformalization 基准各自存在，**没有"检索 → 骨架生成 → 内核验证 → 依赖导航"的闭环**。

**为什么现在**。①**长上下文第一次够用**：openPangu-2.0-Flash 原生 **512K 上下文**（满上下文压缩 KV 仅约 **12GB**），使"把大库索引送进上下文做检索式推理"工程可行；②**代码生成能力强**：该模型官方基准 **LiveCodeBench V6 85.1**，对应 Lean 代码生成；③**Agent 循环能力**：**TAU2-Bench 88.0**，对应"检索 → 编译 → 按报错修正"的多步工具循环。

**开源空白**（带检索式，基准日 2026-10-15）：

| 检索式（GitHub repo 检索） | total_count | 结论 |
|---|---|---|
| `mathlib theorem retrieval benchmark` | **0** | 空白 |
| `formal math library benchmark long context` | **0** | 空白 |
| `openpangu-2.0` | 4 | 2.0-Flash 相关仅两个推理引擎仓库，**零应用层** |

**软论据（辅助，不与硬论据并列；这些是**可对标的既有件**）**：`loganrjmurphy/LeanEuclid`(144★，欧氏几何 autoformalization 基准)、`patrik-cihal/lean-graph`(55★，Lean4 定理依赖图)、`marcusm117/ProofNet-Verified`(1★)、`lean-dojo/ITPEval`(4★)、`Sequential-Intelligence-Lab/MathlibLemma`(2★)、`Xiaoyun-0922/Lean4-Faithful-Translator`(1★)、`ruplet/lean4-eros-vs-aphrodite`(0★)、`vbipba/PROOF-CHECKER`(0★)。**各有单点，但无"检索 + 骨架生成 + 内核验证 + 公开基准"闭环**。

## 二、任务要求

> **首期范围限定**：首期实装 4 个模块（①–④），其余列扩展项（§六）。共用工程底座：**版本化库索引 + 命题/骨架模型 + 内核判定语义 + 证据链 + 基准**。

### 1）命题摄入与形式化草稿

- **输入**：自然语言数学命题（或含已知形式的命题，如"对任意正整数 n，…"）。
- **输出**：Lean 4 statement **草稿**（含类型签名）+ 形式化置信度标记 + 未确定项清单。
- **引擎**：模型在环（可插拔开关，默认关）；关闭时只接受**已形式化的 Lean 输入**。
- **确定性纪律**：**草稿必标 `draft`，未编译通过不得称"形式化成功"**；模型输出的类型签名必须经 Lean 解析器**语法校验**（不通过即报错，不得静默修补）；命题的形式化忠实度**不承诺自动保证**（列为边界）。

### 2）mathlib4 检索

- **输入**：命题 / statement / 关键词。
- **输出**：可复用定理候选 Top-K + **命中证据**（定理名、签名、来源模块、依赖距离）。
- **引擎**：确定性检索（BM25 等，零模型）；**语义 rerank 为显式开关扩展项**。
- **确定性纪律**：**检索底座 = mathlib4 版本化快照（挂 commit hash）**，随仓只存**索引元数据**（定理名/签名/依赖边），**不随仓分发完整源码**；同输入同结果可复跑；**未装 Lean 工具链时检索仍可用**（降级路径必须真实存在）。

### 3）证明骨架生成 + 内核验证（旗舰）

- **输入**：命题 + 模块②的候选定理。
- **输出**：可编译的 Lean 4 **证明骨架**（`sorry` 占位显式标注）+ **内核判定结果**（通过 / 失败）+ 报错定位 + 修正建议。
- **引擎**：模型在环（生成）；**Lean 内核（判定，硬真值）**；Agent 循环（编译 → 按报错修正）为显式开关。
- **确定性纪律**：
  - **Lean 内核编译结果是硬真值**——通过/失败**无歧义**，不需要"评分"；
  - **`sorry` 占位不得计入"证明成功"**（占位即未证明，报告须显式区分"编译通过但含 sorry"与"编译通过且无 sorry"）；
  - **不承诺"免安装 exe 内自举 Lean 工具链"**（见 §六 前置条件边界）：工具只对**声明的代码片段 / 预编译缓存**做验证，**不对全库重编译**；
  - 内核判定与模型生成**在报告里分离呈现**（防"模型说对了"被读成"内核验证通过"）。

### 4）依赖图与导航

- **输入**：模块①的 statement + 模块②③的定理引用。
- **输出**：**定理依赖图**拓扑 + 断链检出（引用了索引中不存在的定理名）+ 最短引用路径 + 可导出 HTML（**0 外链**）。
- **引擎**：确定性图算法（零模型）。
- **确定性纪律**：断链检出**必须区分"索引中不存在"与"索引未覆盖该模块"**（后者标 `index_gap`，不得判为"定理不存在"）；HTML 无外链（守门扫描）。

### 5）内置评测基准（旗舰，硬真值）

- **输入**：合成/公开题库 + **预置模型输出快照**。
- **输出**：指标表——**检索 Recall@k / MRR**、**骨架编译通过率**（分母含含 sorry 者，须分别报"通过且无 sorry"与"通过但含 sorry"）、依赖图完整率、按题型/定理域登记的覆盖度。
- **引擎**：基准 runner（零模型）+ Lean 内核（验证）。
- **确定性纪律**：
  - **真值 = Lean 内核编译结果**（系列中"可核验真值"最强的一类，无需合成真值台账）；
  - 合成命题生成器（已知可形式化/不可形式化的对照）+ 预置快照使指标不依赖当场跑模型；
  - 覆盖度口径：按题型（代数/分析/组合/数论…）与定理域设**最低覆盖项**，写进 manifest；**新增题型而无用例 → 生成器直接报错**。

## 六、边界与非目标（含**前置条件边界**，本题关键）

- **前置条件边界（交付物可达性预检的落地）**：
  - **Lean / elan 工具链 = 用户自备的前置条件**（题面与 README 显式声明，含版本要求与安装指引 ⬜ 待核对）；
  - **mathlib4 全量编译极重（数 GB 磁盘、小时级）——本工具绝不承诺"免安装 exe 内自举 Lean 工具链"**；
  - 工具只对**声明的代码片段 / 预编译缓存**做内核验证，**不对全库重编译**；
  - mathlib4 以**版本化快照（挂 commit hash）**接入，随仓**只存索引元数据**（定理名/签名/依赖边），**不随仓分发完整源码**；
  - **未装 Lean 工具链时**：检索与依赖图功能**降级可用**（该降级路径必须真实存在，并在报告里显式标注"内核验证未执行"）。
- **不做**：数学 OCR；Lean 之外的证明助手适配（扩展项）；证明的"自动完成"（本工具产出骨架与占位，不宣称补全全部 `sorry`）；对模型能力的评分排名。
- **确定性纪律（口径）**：检索/依赖图必须可离线复跑且同输入同结果；**模型接入是可插拔显式开关（OpenAI 兼容端点 / llama.cpp server / omni-infer），默认关闭，不随包分发模型权重**；内核判定由用户自备的 Lean 执行；基准用预置快照使指标不依赖当场跑模型。
- **判定边界**：**编译通过但含 `sorry` ≠ 证明完成**；`index_gap`（索引未覆盖）≠ "定理不存在"；**模型生成与内核判定在报告中分离**，不得混述。
- **免责红线**：检索候选与骨架均为**建议**；形式化忠实度（自然语言命题 → Lean statement 是否等价）**不承诺自动保证**，须人工确认。
- **隐私红线**：全本地存储、零上传；模型开关开启时仅发送用户选中的命题/代码片段，设置页明示。
- **品牌隔离**：不复制姊妹项目代码；文档不提及其余项目的业务领域。
