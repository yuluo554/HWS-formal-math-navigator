## 一、mathlib4 索引抽取算法

### 1.1 输入与输出

| 项目 | 说明 |
|------|------|
| **输入** | mathlib4 版本化快照（commit hash 固定） |
| **输出** | 索引元数据（定理名/签名/依赖边）+ manifest（commit hash + sha256） |
| **不入仓** | mathlib4 完整源码（数 GB） |

### 1.2 索引抽取流程

```
mathlib4 快照（用户自取）
        ↓
┌─────────────────────┐
│ 1. 扫描 .lean 文件   │
│    - 递归扫描 src/   │
│    - 过滤 .git/ 等   │
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 2. 解析定理声明      │
│    - 提取 theorem/lemma/def 名 │
│    - 提取类型签名（冒号后内容） │
│    - 提取模块路径（文件→模块名）│
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 3. 提取依赖边        │
│    - 解析 import 语句 │
│    - 解析 using 语句  │
│    - 构建定理→定理引用图│
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 4. 生成索引元数据    │
│    - theorems.jsonl  │
│    - 每行：{module, name, signature, deps, line} │
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 5. 生成 manifest     │
│    - commit_hash     │
│    - sha256（索引文件）│
│    - generation_date │
└─────────────────────┘
```

### 1.3 索引元数据格式

```jsonl
{"module":"Mathlib.Algebra.Group.Defs","name":"add_assoc","signature":"∀ {α : Type u_1} [Add α] [AddSemigroup α] (a b c : α), a + b + c = a + (b + c)","deps":["Mathlib.Algebra.Group.Defs","Mathlib.Init"],"line":42}
```

### 1.4 确定性纪律

| 纪律 | 落点 |
|------|------|
| **同输入同结果** | 固定 seed；文件扫描按文件名排序；JSON 按 key 排序 |
| **不存源码** | 只存定理名/签名/依赖边；源码由用户自取 |
| **版本固定** | commit hash 写入 manifest；重建索引可复跑 |
| **sha256 留档** | 索引文件 sha256 写入 manifest；发布前校验 |

## 二、检索算法（BM25，零模型）

### 2.1 算法选择

| 算法 | 选型 | 理由 |
|------|------|------|
| **主检索** | BM25 Okapi | 经典、可解释、零模型依赖 |
| **语义 Rerank** | 扩展项（显式开关） | 首期不强制；用户可自选 |

### 2.2 BM25 参数

| 参数 | 值 | 说明 |
|------|-----|------|
| **k1** | 1.2 | 词频饱和度 |
| **b** | 0.75 | 文档长度归一化 |
| **δ** | 0.0 | 文档长度平滑（首期不启用） |

### 2.3 检索流程

```
输入：命题 / statement / 关键词
        ↓
┌─────────────────────┐
│ 1. 查询预处理        │
│    - 分词（按空格+符号）│
│    - 过滤停用词（可选） │
│    - 词干化（可选）    │
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 2. 索引匹配          │
│    - 定理名匹配（高权重）│
│    - 签名匹配（中权重） │
│    - 模块名匹配（低权重）│
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 3. BM25 评分         │
│    - 计算每个定理得分 │
│    - 按得分排序       │
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 4. 返回 Top-K        │
│    - 默认 K=10       │
│    - 含命中证据：     │
│      · 定理名        │
│      · 签名          │
│      · 来源模块      │
│      · 依赖距离      │
└─────────────────────┘
```

### 2.4 命中证据格式

```json
{
  "theorem": "add_assoc",
  "module": "Mathlib.Algebra.Group.Defs",
  "signature": "∀ {α : Type u_1} [Add α] [AddSemigroup α] (a b c : α), a + b + c = a + (b + c)",
  "score": 0.85,
  "match_fields": ["name", "signature"],
  "dep_distance": 3,
  "source": "index"
}
```

### 2.5 确定性纪律

| 纪律 | 落点 |
|------|------|
| **同输入同结果** | 排序按 score 降序；同分按定理名字典序 |
| **可复跑** | 索引固定；算法确定性；无随机因素 |
| **降级可用** | 无 Lean 工具链时检索仍可用（索引已入仓） |

## 三、骨架生成与 Agent 循环

### 3.1 骨架生成流程

```
输入：命题 + 候选定理（来自检索）
        ↓
┌─────────────────────┐
│ 1. 命题形式化（模型在环）│
│    - 模型生成 Lean 4   │
│    - 含类型签名        │
│    - 标记 draft 状态   │
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 2. 语法校验（确定性）  │
│    - Lean 解析器校验  │
│    - 不通过即报错      │
│    - 不静默修补        │
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 3. 骨架生成          │
│    - 插入 sorry 占位  │
│    - 引用候选定理     │
│    - 生成证明结构     │
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 4. 输出              │
│    - Lean 4 代码片段  │
│    - draft 标记       │
│    - 未确定项清单     │
└─────────────────────┘
```

### 3.2 模型接入网关

```python
class ModelGateway:
    """模型接入网关（可插拔开关）"""

    def __init__(self, config: Config):
        self.enabled = config.model.enabled
        self.endpoint = config.model.endpoint
        self.llama_cpp_path = config.model.llama_cpp_path
        self.omni_infer_url = config.model.omni_infer_url

    def generate_skeleton(self, prompt: str) -> SkeletonResult:
        if not self.enabled:
            raise ModelDisabledError("模型已关闭，请启用后重试")

        # 按端点类型分发
        if self.endpoint:
            return self._call_openai_endpoint(prompt)
        elif self.llama_cpp_path:
            return self._call_llama_cpp(prompt)
        elif self.omni_infer_url:
            return self._call_omni_infer(prompt)
        else:
            raise ModelConfigError("未配置模型端点")
```

### 3.3 Agent 循环（显式开关）

```
输入：初始骨架
        ↓
┌─────────────────────┐
│ 1. 编译骨架          │
│    - 调用 Lean 内核  │
│    - 获取报错信息    │
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 2. 分析报错          │
│    - 定位错误位置    │
│    - 分类错误类型    │
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 3. 模型修正（可选）  │
│    - 生成修正建议    │
│    - 应用修正        │
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 4. 循环判断          │
│    - 成功？→ 输出    │
│    - 失败？→ 重试    │
│    - 超限？→ 报错    │
└─────────────────────┘
```

### 3.4 确定性纪律

| 纪律 | 落点 |
|------|------|
| **模型默认关闭** | 配置项 `model.enabled = false` |
| **不静默修补** | 语法校验不通过即报错，不自动修正 |
| **sorry 显式标注** | 骨架中所有 sorry 占位显式标注 |
| **报告分离** | 模型生成与内核判定在报告中分离呈现 |

## 四、内核判定语义

### 4.1 判定结果三态

| 状态 | 含义 | 报告呈现 |
|------|------|----------|
| **PASS_NO_SORRY** | 编译通过且无 sorry | ✅ 证明完成 |
| **PASS_WITH_SORRY** | 编译通过但含 sorry | ⚠️ 骨架完成（未证明） |
| **FAIL** | 编译失败 | ❌ 证明失败 |

### 4.2 判定流程

```
输入：Lean 4 代码片段
        ↓
┌─────────────────────┐
│ 1. 检查 Lean 可用性  │
│    - 检测 lean 命令  │
│    - 不可用 → 降级   │
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 2. 调用内核验证      │
│    - lean --check    │
│    - 捕获输出        │
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 3. 解析结果          │
│    - 提取编译状态    │
│    - 提取报错信息    │
│    - 检测 sorry 存在 │
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 4. 输出判定结果      │
│    - 状态（三态）    │
│    - 报错定位        │
│    - 修正建议        │
└─────────────────────┘
```

### 4.3 判定结果格式

```json
{
  "status": "PASS_WITH_SORRY",
  "has_sorry": true,
  "sorry_count": 3,
  "sorry_locations": ["line 15", "line 23", "line 42"],
  "errors": [],
  "warnings": [],
  "kernel_version": "Lean 4.15.0",
  "verification_time_ms": 1234
}
```

### 4.4 确定性纪律

| 纪律 | 落点 |
|------|------|
| **硬真值** | 内核编译结果 = 唯一真值，无歧义 |
| **sorry 不计入成功** | 报告分列"通过且无 sorry"与"通过但含 sorry" |
| **报告分离** | 模型生成与内核判定在报告中分离呈现 |
| **降级标注** | 无 Lean 工具链时报告标注"内核验证未执行" |

## 五、依赖图算法

### 5.1 图构建

```
输入：定理引用（来自索引）
        ↓
┌─────────────────────┐
│ 1. 构建依赖图        │
│    - 节点：定理      │
│    - 边：依赖关系    │
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 2. 拓扑排序          │
│    - 检测环          │
│    - 生成依赖顺序    │
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 3. 最短路径          │
│    - BFS 求最短引用路径│
└─────────────────────┘
        ↓
┌─────────────────────┐
│ 4. 断链检出          │
│    - 引用定理不在索引 │
│    - 区分 index_gap  │
└─────────────────────┘
```

### 5.2 断链检出语义

| 状态 | 含义 | 处理 |
|------|------|------|
| **BROKEN** | 引用定理不在索引中 | 标为断链，提示用户 |
| **INDEX_GAP** | 索引未覆盖该模块 | 标为 index_gap，不判为"定理不存在" |

### 5.3 依赖图输出

```json
{
  "nodes": [
    {"id": "add_assoc", "module": "Mathlib.Algebra.Group.Defs"},
    {"id": "add_comm", "module": "Mathlib.Algebra.Group.Defs"}
  ],
  "edges": [
    {"from": "add_comm", "to": "add_assoc", "type": "depends_on"}
  ],
  "broken_refs": [],
  "index_gaps": ["Mathlib.Tactic.Suggest"],
  "shortest_paths": {
    "add_assoc": ["add_comm", "add_assoc"]
  }
}
```

### 5.4 HTML 导出（0 外链）

| 纪律 | 落点 |
|------|------|
| **0 外链** | HTML 内嵌 CSS/JS；无 CDN 引用；断网可开 |
| **守门扫描** | 构建时扫描 HTML 外链；发现即报错 |

## 六、口径单一定义点

### 6.1 核心口径

| 口径 | 定义点 | 不可改动 |
|------|--------|----------|
| **sorry 不计入成功** | 内核判定器 `KernelResult` | 测试覆盖 |
| **index_gap ≠ 定理不存在** | 依赖图断链检出器 | 测试覆盖 |
| **模型生成与内核判定分离** | 报告模板 | 测试覆盖 |
| **同输入同结果** | 检索器排序 | 测试覆盖 |
| **Lean 工具链用户自备** | README + 配置 | 测试覆盖 |

### 6.2 口径变更流程

```
1. 提出变更 → 2. 评估影响面 → 3. 更新代码 → 4. 更新测试 → 5. 更新文档 → 6. 登记决策记录
```
