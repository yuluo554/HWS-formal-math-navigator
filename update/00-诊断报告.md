## 三、缺陷清单

### D1【P1】pip 渠道装完不可用：`data/` 既不进 wheel 也不进 sdist

- **现象**：`pip install` 后从任意目录运行，`selftest`/`search`/`export`/`bench` 全部失败，因为 `Config.data_dir` 默认是 **CWD 相对的 `data/`**（`src/hws_formal_math/config.py:default_data_dir()`），而 wheel/sdist 内根本没有任何 `data/` 文件。
- **实测**（干净 venv `%TEMP%\fmndiag\.venv-wheel`，中立目录 `%TEMP%\fmndiag\neutral`，`pip install hws_formal_math_navigator-0.1.1-py3-none-any.whl` 后）：
  ```
  hws-formal-math selftest            → ERROR 索引目录不存在: data\index            exit 1
  hws-formal-math search "加法结合律"  → ERROR 检索失败: 索引目录不存在: data\index   exit 1
  hws-formal-math bench --suite retrieval → 未找到基准用例目录 tests/fixtures         exit 2
  hws-formal-math export -o out/report.html → ERROR 导出失败: 索引目录不存在          exit 1
  python -m hws_formal_math.viewer --selftest → ❌ 索引 manifest 不可读: 'data\index\manifest.json'  exit 1
  ```
- **反证（证明唯一卡点就是数据位置）**：同一 venv 加 `--index-path <repo>/data/index` 并临时拷入 `tests/` 后：
  `selftest` → exit 0（35 条）、`bench --suite retrieval` → exit 0（Recall 0.9）。
- **包内容实证**：wheel 31 个条目，**零 `data/`**；sdist 62 个条目，**零 `data/`、零 `tests/fixtures/`、零 `tests/conftest.py`**。【实测 `zipfile.namelist()` / `tar tzf`】
- **sdist 连带问题（并入本项，不单列）**：sdist 里 `tests/` 有 14 个测试文件但缺 `conftest.py`、`fixtures/`、`tools/`：
  `python -m pytest tests/ -q` → **2 个 collection error**（`ModuleNotFoundError: No module named 'tools'`），**exit 2**。
- **README 冲突**：README §下载即用 写「自检（索引数据随包分发，无需额外下载）」——对 zip 成立，对 pip 不成立，且未说明 pip 安装必须 `cd` 到仓根。`RELEASE-NOTES.md` 同样问题。

### D2【P1】内核验证的调用方式在上游 Lean 4 里不存在：`lean --check` 不是合法选项

- **现象**：`src/hws_formal_math/engine/kernel.py::_run_lean_check` 执行 `[lean, '--check', temp_file]`。Lean 4 的命令行**没有 `--check`**。
- **上游源码直读**（抓取 `leanprover/lean4` master）：`src/util/shell.cpp` 的 `g_long_options[]` 完整选项表里无 `check`；`src/Lean/Shell.lean::displayHelp` 的帮助文本也无该选项；同一文件 `processOptions` 的未知分支是 `| _ => pure ()`，随后 `eprint "Unknown command line option\n"` 并 `throw 1`（即 **exit 1**）。
- **本地等价实测**（把 `python.exe` 复制成 `lean.exe` 冒充，验证"rc≠0 → FAIL"这条映射）：
  ```
  KernelVerifier(lean_path=...\fakelean\lean.exe).verify("theorem t : True := by trivial")
  → status FAIL, errors[0] = 'unknown option --check'
  ```
- **后果**：真装 Lean 后，**正确证明也会被判 FAIL（exit 1）**，`PASS_NO_SORRY` 永远达不到。这直接摧毁"内核硬真值"这条卖点。
- **未验证部分（如实标注）**：本机无 Lean/elan（`command -v lean` 无输出、`~/.elan` 不存在），**未在真 Lean 上跑过**。所以定性为「上游源码直读 + 本地等价映射实测」，不是「真 Lean 实测」。
- **附加缺口**：`skeleton` 套件的阈值常量（`PASS_NO_SORRY_MIN=0.30`、`PASS_WITH_SORRY_MIN=0.50`）在 CI 与发布物中**从未被执行过一次**（CI 无 Lean，永远 `not_enabled`）；`tests/test_kernel.py` 12 项全部走 `shutil.which=None` 或只测正则，**没有任何一项覆盖真实子进程调用**（`grep -rn "_run_lean_check" tests/` → 0 命中）。

### D3【P1】发布形态门禁假通过：子串判定让"只有查看器"的 zip 报"含 CLI + 查看器"

- **现象**：`tools/assert_release_shape.py` 用 `any(CLI in n for n in names)` 判 zip 是否含 CLI，而 `CLI = "hws-formal-math"` 是 `VIEWER = "hws-formal-math-viewer"` 的**前缀**。zip 里只要有两个 `.exe` 中的查看器，两条断言同时命中。
- **负控实测**（构造 `dist/hws-formal-math/{CLI,VIEWER}.exe` 但 zip 内**只放查看器**）：
  ```
  rc = 0
  ✅ 冻结产物含双 exe：hws-formal-math / hws-formal-math-viewer
  ✅ only-viewer-win64.zip 内含 CLI + 查看器
  ```
  → 门禁**放行了一个缺 CLI 的 zip**。这正是「失效模式 #12：门禁 script 报了 PASS 但实质缺口」。
- **CI 里它是唯一形态门**（`.github/workflows/ci.yml` 的 `Assert release shape (CLI + viewer)`），所以 `preflight ㉕` 的机械落点是空的。

### D4【P1】冻结数据属性只覆盖第 1 层：真正承载 sha256 的 `v1/*.json` 没有被 `-text` 冻结

- **现象**：`.gitattributes` 写的是 `data/index/*.jsonl`、`data/snapshots/*.json`、`data/proposals/*.json`——**不匹配 `data/snapshots/v1/snapshots.json` 这类二级路径**。
- **实测 `git check-attr -a`**：
  ```
  data/index/theorems.jsonl          : text: unset      ← 命中，已冻结
  data/snapshots/manifest.json       : text: unset      ← 命中
  data/snapshots/v1/snapshots.json   : text: auto, eol: lf   ← ❌ 未冻结
  data/proposals/v1/proposals.json   : text: auto, eol: lf   ← ❌ 未冻结
  ```
- **已发生的字节漂移（实测）**：`git ls-files --eol data/proposals/v1/proposals.json` → `i/lf  w/crlf`；工作树 11,776 B（含 506 个 CRLF），`git clone` 出来的副本 11,270 B（LF）。**同一文件在两处字节不同**——只是 `proposals` 的 manifest 没有 `sha256` 字段，所以没人发现。
- **风险**：`snapshots.json` 的 sha256 恰好被写进了 `manifest.json`（`fcf7aaf7…`，与 LF 版本一致），目前侥幸对得上；一旦生成器在某平台写出 CRLF，`fcf7aaf7…` 就会失真，而**没有任何门在核**（`grep -rn sha256 src/` → 0 命中，运行时不校验 manifest 的 sha256）。

- 对审计的伤害：这正是「失效模式 #13：证据被同名覆盖」。`--check` 应当只读。
